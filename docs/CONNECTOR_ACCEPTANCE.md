# Live WordPress acceptance

Automated API/SQL and isolated PHP contract tests are not live WordPress acceptance. Use a disposable single-site WordPress 6.5+ installation with PHP 8.1+ and an HTTPS SitePulse staging origin, private PostgreSQL, valid TLS, and a configured authentication sender. Do not run production migrations or expose database/API ports for this procedure.

The latest attempt and missing environment prerequisites are recorded in [STAGING_ACCEPTANCE_REPORT.md](STAGING_ACCEPTANCE_REPORT.md). Local Docker startup and health checks now pass; live HTTPS WordPress and real mail acceptance remain pending.

1. Run frozen dependency installation, `pnpm check`, `pnpm test:integration`, `pnpm test:plugin`, `pnpm build`, `pnpm db:check`, `pnpm compose:check` and dependency audit. Apply migrations only to authorized staging data after backup. Start web/API and the heartbeat worker.
2. Register two users, receive a real verification email, confirm it and verify password recovery revokes an old session. Create separate organizations. Confirm a guessed foreign site URL/API ID yields 404, and unverified accounts cannot manage sites.
3. As the verified owner, register the WordPress home URL including its subdirectory. Generate a code. Copy/zip plugins/sitepulse-connector to the WP plugins directory, activate, and pair through Settings → SitePulse with your HTTPS origin. Confirm the initial heartbeat makes the dashboard active and its last receipt time advances.
4. Verify a non-administrator cannot open settings or submit pairing/disconnect actions. Reject a missing/bad nonce. Ensure page source, browser URLs, logs and audit rows contain no pairing code, credential or reset link. The deliberate one-time code display and WP non-autoloaded secret option are expected exceptions.
5. Reuse and expire pairing codes; both must fail. Generate two codes; only the newest should work. Send duplicate heartbeat sequences through the test harness; they must return 409 and must not refresh last_seen_at.
6. Rotate the credential in the SaaS. Confirm the old plugin fails heartbeat, disconnect its now-invalid local connection, and pair with the fresh code. Confirm a valid heartbeat recovers. Disconnect normally in WordPress; confirm the server refuses further use of the old credential.
7. Deactivate and confirm scheduled SitePulse hooks are removed. Reactivate and confirm a preserved connection resumes. Pair again if revoked. With WP-Cron paused, wait beyond the configured stale window (default 45 minutes plus up to one worker poll); confirm one stale audit event and degraded state. Resume cron, confirm active recovery. Repeat with a paired site that never sends its first heartbeat.
8. Simulate API timeout and TLS failure; confirm generic errors, bounded retry intervals, preserved disconnect credential on network error, and no request from ordinary frontend page rendering. Drive WP-Cron from system cron for predictable intervals. Confirm multisite activation is blocked.
9. Before disconnecting, run a connector sync and confirm site detail receives WordPress/PHP versions, active plugins/themes and update counts. Activate/deactivate a disposable plugin, sync again and confirm the snapshot is replaced with a new server receipt timestamp. Confirm payloads contain no content, settings or credentials. Another tenant must receive 404 for the site/inventory and a revoked or foreign site credential must not replace its snapshot. Empty inventory must display a waiting state without crashing the page.
10. Explicitly disconnect, uninstall the plugin, and confirm local options and events are removed. Soft delete the site in the API, confirm hidden reads/invalid credentials, and verify another tenant cannot mutate any lifecycle endpoint.

Record WP/PHP/PostgreSQL versions, HTTPS/proxy configuration, results, sanitized screenshots/log evidence and limitations. No actual customer data or credentials belong in evidence. External uptime/SSL checks and incidents have their own procedure in MONITORING_ACCEPTANCE.md; alert delivery and billing are outside this acceptance scope. Do not progress to public pilots on contract-test results alone.
