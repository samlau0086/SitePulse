# SitePulse WordPress connector

Requires WordPress 6.5+, PHP 8.1+ and single-site WordPress. Copy this directory to wp-content/plugins/sitepulse-connector, or zip the directory and install it through Plugins → Add New → Upload Plugin. Activate, then open Settings → SitePulse as an administrator. Enter the public SitePulse HTTPS origin and the short-lived code generated by a verified workspace administrator. The registered site URL must match home_url, including subdirectories. The plugin sends a test heartbeat immediately and schedules a new one every 15 minutes.

Requests use wp_safe_remote_post with verified TLS and no redirects. The connector sends site ID, increasing sequence, connector version, WordPress/PHP versions, installed plugin/theme identifiers and versions, active/update state, update counts, selected environment flags, and bounded local security rule IDs with paths relative to `wp-content`. WP-Cron is traffic-driven: configure a system cron invocation if precise timing is required. Failures retry after 60, 120, 240, 480, then 900 seconds; the delay remains capped at 900 seconds until success. Sequence is advanced even when a response times out.

The read-only local scan visits at most 5,000 entries, reads at most 500 PHP-like/JavaScript files and 512 KiB per file, returns at most 100 indicators, and caches results for six hours. An explicit inventory-sync request refreshes that scan. It never uploads file contents or absolute paths and never modifies or quarantines code. Matches require human review; no match is not proof that the site is safe. Customer database content, plugin settings and administrator passwords are never collected. See `docs/SECURITY_INVENTORY.md` in the repository.

Connector 0.4.0 keeps plugin/theme management and uploaded-package installation disabled by default. A WordPress administrator with current capabilities must enable ordinary remote management and separately opt in to uploaded package installation. The latter permission is never inferred from the former. Approved packages are fetched only from the stored paired SitePulse HTTPS origin with the site bearer and a short-lived operation lease, with redirects disabled and an 8 MiB bound. The connector rechecks consent and SHA-256 after download, installs through WordPress native upgraders, and deletes the temporary file on success or failure. It does not accept arbitrary URLs, shell/SQL/PHP editing commands or FTP/SSH credentials. Uploaded code can execute normal WordPress installation/activation hooks, so back up the site and trust the package source even when the SitePulse static scan reports no selected findings.

The credential is held in a non-autoloaded WP option and never rendered in HTML or logged. Protect database access and backups. Disconnect revokes the server credential before removing local state; network failures retain it for retry. A 401 permits removing an already invalid credential. After SaaS rotation, disconnect the old WP connection and enter the new code. Deactivation clears scheduled events but preserves connection data for revocation/reactivation. Disconnect before uninstalling: uninstall only deletes local options and events and cannot guarantee server revocation. Multisite is explicitly blocked.

Run `pnpm test:plugin` from the repository root with PHP 8.1+ in PATH (or set PHP_BIN). Tests use isolated WordPress contract doubles; they cover security guards, response validation, safe HTTP settings, retry bounds, replay sequences, redacted HTML, and lifecycle cleanup. Follow docs/CONNECTOR_ACCEPTANCE.md for live acceptance.
